# 인덱스 — 학습 가이드라인

> 아직 시작 전. 이 파일은 **계획**이고, 실습하면서 측정값과 내 설명으로 채운다.

## 왜 이걸 먼저 하나

```
 쿼리 작성        손 코딩 과제로 나온다          1번 정도
 DB 이론          면접 질문으로 나온다           거의 매번
```

신입 백엔드 DB 질문은 거의 이 범위다.

```
 "인덱스가 뭔가요?"
 "인덱스를 걸면 왜 빨라지죠?"
 "인덱스를 탔는데도 느리면요?"
 "트랜잭션 격리 수준 설명해보세요"
 "Deadlock 은 왜 생기나요?"
```

## 원칙 — 숫자를 봐야 한다

```
 인덱스 설명을 읽는다              "아 그렇구나"   →  안 남는다
 10만 건에서 2초 → 0.001초         "와"           →  남는다
```

네트워크 실습(tcpdump, UDP 유실률)과 같은 방식. **측정 가능한 산출물**을 만든다.

## 데이터는 따로 만든다

```
 shop.db     15~40행.  SQL 문제용.  건드리지 않는다
 bench.db    100만 행.  인덱스 실습 전용        ← 새로 만든다
```

100건에 인덱스를 걸면 차이가 0이다. 오히려 풀스캔이 빠를 수도 있다.
**규모를 만드는 것이 첫 작업.** SQLite 재귀 CTE 로 생성한다.

```
 cs/db/_bench_schema.sql    생성 스크립트 (추적)
 cs/db/bench.db             결과물 (gitignore — *.db 이미 등록됨)
```

## 1회차 — 인덱스가 있고 없고 (40분)

```
 ① 사전 진단        "인덱스가 뭐라고 생각하세요?"  2~3문항
 ② 100만 건 생성
 ③ 인덱스 없이 조회   .timer on 으로 시간 측정
                    EXPLAIN QUERY PLAN  →  SCAN  (풀스캔)
 ④ 인덱스 생성       CREATE INDEX
 ⑤ 같은 쿼리 재측정   SEARCH USING INDEX  →  시간 비교
 ⑥ 왜 빨라지나       B+Tree 구조.  100만 건을 3~4번 만에 찾는 이유
 ⑦ 공짜가 아니다     INSERT 100만 건을 인덱스 전/후로 측정    ★
```

**⑦이 중요하다.** 인덱스를 "걸면 좋은 것"으로만 알면 면접에서 한 수 아래로 보인다.

```
 인덱스를 알면       "느리니까 인덱스 걸죠"
 인덱스를 이해하면    "쓰기가 많은 테이블이라 신중해야 합니다"
```

## 2회차 — 인덱스를 못 타는 경우 (40분)

```
 ① LIKE '%검색어'            앞이 뚫리면 못 탄다
 ② WHERE 컬럼에 함수 적용      substr(name,1,2) = '무선'
 ③ 타입 불일치
 ④ 복합 인덱스 순서 위반        (a,b) 인덱스에 b 만으로 조회
 ⑤ 카디널리티가 낮을 때         값이 2~3개뿐이면 안 타는 게 낫다
 ⑥ 옵티마이저가 거부           전체의 20~30% 이상이면 풀스캔이 더 빠르다
```

**⑥이 면접에서 갈리는 지점.** "인덱스를 걸었는데 왜 안 타나요?"의 답이 여기 있다.

## 이론은 실습 사이에 끼운다

```
 ❌  B+Tree 를 먼저 강의하고 실습
 ✅  측정으로 "빨라진다" 를 본 뒤에 "왜" 를 설명
```

## SQLite 한계 — 미리 알고 간다

```
 SQLite 로 되는 것      B-tree 인덱스,  EXPLAIN QUERY PLAN,  복합 인덱스
                      → 원리 학습엔 충분하다

 MySQL 과 다른 것       클러스터드 인덱스 (PK 기준 물리 정렬)
                      커버링 인덱스
                      EXPLAIN 출력 형식 (type, key, rows, Extra)
                      옵티마이저 통계 / ANALYZE
```

원리는 같다. MySQL 특유의 것은 설명으로 보완한다.
Docker MySQL 이 필요해지면 그때 규칙 변경을 받는다. (현재 기술 제약: H2 / SQLite)

## 이 다음

```
 인덱스  →  트랜잭션 / 격리 수준  →  락 / 데드락
                                      ↑
                              과제 #3 STEP 3 와 바로 이어진다
```

**락은 과제 #3 안에서 배운다.** 100장인데 103장이 나가는 걸 본 직후에 이론을 붙이는 게,
미리 읽고 과제에 들어가는 것보다 훨씬 남는다.

**인덱스는 과제로 안 된다.** 쿠폰 과제의 데이터는 100건 수준이라 측정할 게 없다.
그래서 별도 실습으로 뺐다.
