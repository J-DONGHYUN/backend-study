## ⏭ 다음 세션에서 먼저 복습할 것 (🔴🟡 중 우선순위)
1. **생성자 주입 네 가지** — 명시성·테스트 용이성·불변·불완전객체 방지. 2026-10-16 기준 2개만 (하나는 유도)
2. **Entity를 응답으로 직접 반환하면 안 되는 이유** — 2회 연속 민감정보에서 멈춤(10/08, 10/21).
   **"그건 @JsonIgnore 로 되지 않나요?" 라는 되물음에 답할 수 있어야 한다**
3. **Entity에 `@Setter`를 쓰지 않는 이유** — "중요한 정보라서"는 모호. **도메인 규칙 우회**가 핵심
4. **Spring MVC = Front Controller 패턴** — 2026-10-13 구술에서 또 "MVC 패턴"이라 부름 (두 번째)
4-1. **JSON ↔ DTO 를 누가 하는가** — MessageConverter(Jackson). `@RestController` 가 바꾸는 게 아니다.
   **10/13, 10/21 두 번 다 같은 자리에서 주어가 빠졌다**
5. **flush — create는 불필요하고 update/addComment는 필요한 이유** — 과제 #2 체크리스트 12개 참고
6. **TCP 는 스트림이라 메시지 경계가 없다** — `Content-Length` 가 필요한 이유 (2026-10-10 틀림)
6-1. **ACK 와 재전송의 주체** — ACK 는 받은 쪽이, 재전송은 보낸 쪽이. 2026-10-21 둘 다 반대로 답함
7. ~~**`LEFT JOIN` + `COUNT(*)` 함정**~~ — 2026-10-13 해결 (🟢)
8. ~~**`HAVING` 별칭**~~ — 2026-10-21 우선순위 내림. **트리비아에 가깝다**(3회 질문, 3회 모름).
   실행 순서 자체는 계속 보되, 별칭 금지는 따로 안 묻는다
9. **`EXISTS` 철자** — 손으로 쓸 때 `EXIST` 로 쓴다 (3회)
10. **AOP 프록시 / self-invocation** — 2026-10-22 설명 듣고 이해. **스스로 설명하는지** 재확인 필요
11. **`@Transactional(readOnly)`** — 🟢이지만 본인 요청으로 재확인 대상. 2026-10-16 기준 확인 완료,
    **다음엔 "클래스 레벨에 기본값으로 걸고 쓰기만 덮어쓴다"는 관례까지** 나오는지 본다 (이건 몰랐음)
