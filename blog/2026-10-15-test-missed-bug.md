Todo CRUD API를 만들고 테스트를 18개 짰습니다. 단위부터 E2E까지 층마다 있었고 전부 초록불이었습니다.
그런데 수정 API 응답이 틀려 있었습니다.

---

## 증상

```bash
PUT /todos/1
```

```jsonc
{
  "title": "빨래하기",                   // 수정 반영됨
  "createdAt": "2026-10-07T20:49:38",
  "updatedAt": "2026-10-07T20:49:38"    // 수정 시각이 아니라 생성 시각
}
```

조회해보면 제대로 나옵니다. **DB는 맞고 응답만 틀렸습니다.**

---

## 테스트가 본 곳이 사용자가 받는 곳이 아니었다

```
                      버그가 있는 곳                      테스트가 본 곳
                           │                                │
   요청 ──▶ Controller ──▶ Service ──▶ Repository ──▶ DB
                           │                                │
                      ┌────▼────┐                    ┌──────▼──────┐
                      │ 응답 DTO │                    │   엔티티     │
                      ├─────────┤                    ├─────────────┤
                      │updatedAt│                    │  updatedAt  │
                      │ 옛날 값  │ ❌                 │   최신 값    │ ✅
                      └─────────┘                    └─────────────┘
                           │
                      사용자가 받는 것
```

시각 갱신을 검증하는 테스트는 분명히 있었습니다. 다만 **DB에서 다시 읽은 엔티티**를 봤습니다.

엔티티는 멀쩡합니다. 버그는 거기 없었으니까요.

---

## 그리고 테스트가 버그를 가려줬다

```
  운영 코드                          테스트 코드
 ─────────────────────────────────────────────────────
  update()                          update()
      │                                 │
      │  (flush 없음)                    │  em.flush()    ← 테스트만 한다
      │                                 │  em.clear()
      ▼                                 ▼
  DTO 생성                           DB 에서 다시 조회
      │                                 │
  updatedAt 아직 안 채워짐 ❌          updatedAt 채워짐 ✅
```

**운영 코드에 없는 단계를 테스트가 대신 해줬습니다.** 그 상태로 검증하니 당연히 통과합니다.

테스트가 버그를 찾아낸 게 아니라, **버그가 없는 경로를 따로 만들어서 확인한 셈**입니다.

---

## 그럼 애초에 왜 틀렸나

`updatedAt`은 제가 대입하는 값이 아닙니다. JPA 콜백이 채웁니다.

```java
@PreUpdate
void onUpdate() { this.updatedAt = LocalDateTime.now(); }
```

이름이 "업데이트 직전"이라 **수정하는 순간 도는 줄 알았습니다.** 아니었습니다.

```
  @PreUpdate 가 도는 시점  =  UPDATE 쿼리를 DB 로 내보내기 직전  =  flush
```

그리고 flush는 보통 **커밋할 때** 일어납니다. 그 사이에 제가 DTO를 만들어버린 게 문제였습니다.

```
  시간 ──────────────────────────────────────────────────────▶

  ① todo.update("빨래하기")
         엔티티의 title 만 바뀐다.  updatedAt 은 아직 옛날 값

  ② TodoResponse.from(todo)        ★ 여기서 DTO 를 만든다
         updatedAt = 옛날 값을 복사해 간다

  ─────────────── @Transactional 종료 · 커밋 ───────────────

  ③ flush
       ├─ @PreUpdate 실행   updatedAt = 지금      ← 이제야 채워진다
       └─ UPDATE 쿼리 전송

  결과   DB   updatedAt 최신 ✅
         응답  updatedAt 옛날 ❌
```

**②가 ③보다 먼저입니다.** 아직 채워지지 않은 값을 복사해 간 거죠.

---

## DTO는 복사본이라 나중에 안 바뀐다

```
      엔티티                              응답 DTO (record)
  ┌──────────────┐                    ┌──────────────┐
  │ title   빨래  │                    │ title   빨래  │
  │ updatedAt 옛날│ ───── 복사 ─────▶  │ updatedAt 옛날│
  └──────────────┘                    └──────────────┘
         │                                   │
    ③ flush 에서 갱신                     불변.  안 바뀐다
         ▼                                   ▼
  ┌──────────────┐                    ┌──────────────┐
  │ updatedAt 지금│ ✅                 │ updatedAt 옛날│ ❌
  └──────────────┘                    └──────────────┘
```

엔티티는 나중에 채워지지만, **이미 값을 복사해 간 DTO는 따라가지 않습니다.** 참조가 아니라 값을 떠간 거니까요.

---

## 등록은 왜 멀쩡했을까

같은 구조인데 `POST /todos`는 `createdAt`이 제대로 나왔습니다. 차이는 **누가 persist를 부르느냐**였습니다.

```
  create()                                update()
  ────────────────────────────────────────────────────────────────
  todoRepository.save(todo)               todo.update("빨래하기")
       │                                       │
       │ @GeneratedValue(IDENTITY) 라          │ 아무도 persist 를 안 부른다
       │ INSERT 를 미룰 수 없다                 │ 변경 감지는 flush 때 돈다
       │ (id 를 알려면 넣어봐야 하니까)           │
       ▼                                       ▼
  그 자리에서 INSERT                        그 자리에선 아무 일도 안 일어난다
  @PrePersist 실행 → createdAt 채워짐        @PreUpdate 는 커밋 때
       │                                       │
       ▼                                       ▼
  DTO 생성   createdAt 있음 ✅              DTO 생성   updatedAt 옛날 ❌
```

**등록은 운이 좋았던 겁니다.** IDENTITY 전략이라 INSERT가 즉시 나갔고, 덕분에 `@PrePersist`도 DTO를 만들기 전에 돌았습니다. 전략이 `SEQUENCE`였다면 등록도 똑같이 틀렸을 겁니다.

---

## 정리하면

```
  내가 대입하는 값        title, content          바로 반영된다
  JPA 콜백이 채우는 값     createdAt, updatedAt    flush 때 채워진다
```

```
  DTO 를 만드는 시점에 JPA 가 아직 하지 않은 일은, DTO 에 담기지 않는다
```

고치는 건 응답을 만들기 전에 `flush()`를 부르는 한 줄이었습니다. 순서만 바꾼 거죠.

`@PreUpdate`라는 이름을 "수정할 때 돈다"로 읽은 게 출발점이었습니다. 정확히는 **"UPDATE 쿼리를 내보내기 직전에 돈다"** 였고, 그 둘 사이에 제 코드가 끼어 있었습니다.
