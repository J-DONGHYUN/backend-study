Spring Boot로 CRUD를 만들면 네 단어를 전부 만납니다. 저는 한참 동안 이걸 **"비슷한 것 네 개"** 로 알고 있었습니다. 골라 쓰는 건 줄 알았죠.

**아니었습니다. 넷은 층이 다릅니다.**

```
 Spring Data JPA    인터페이스만 선언하면 구현체를 만들어준다      편의
 ─────────────────────────────────────────────────────
 JPA                명세.  인터페이스와 애노테이션뿐              약속
 ─────────────────────────────────────────────────────
 Hibernate          그 약속을 구현한 코드.  SQL 을 만든다        구현
 ─────────────────────────────────────────────────────
 JDBC               자바가 DB 와 말하는 유일한 통로              표준 API
```

골라 쓰는 게 아니라 **쌓아 쓰는 것**입니다.

---

## 전체 그림

제 토이 프로젝트의 실제 의존성입니다.

```
 내 코드   todoRepository.findById(1L)
     ↓
 ┌──────────────────────────────────────────────────┐
 │  Spring Data JPA      spring-data-jpa             │
 ├──────────────────────────────────────────────────┤
 │  JPA (명세)           jakarta.persistence-api     │
 │     ★ 실행되는 코드가 없다                          │
 ├──────────────────────────────────────────────────┤
 │  Hibernate (구현)     hibernate-core              │
 ├──────────────────────────────────────────────────┤
 │  JDBC                java.sql.*  (JDK 내장)       │
 │     Connection / PreparedStatement / ResultSet    │
 ├──────────────────────────────────────────────────┤
 │  JDBC Driver         h2 / mysql-connector ...     │
 └──────────────────────────────────────────────────┘
     ↓
    DB
```

아래로 갈수록 오래됐고(JDBC 1997, JPA 2006, Spring Data JPA 2011), 위로 갈수록 편합니다.

---

## ① JDBC — 전부 손으로

```java
String sql = "SELECT id, title, completed FROM todo WHERE id = ?";

try (Connection conn = dataSource.getConnection();
     PreparedStatement ps = conn.prepareStatement(sql)) {

    ps.setLong(1, 1L);
    ResultSet rs = ps.executeQuery();

    if (rs.next()) {
        Todo todo = new Todo();
        todo.setId(rs.getLong("id"));            // 한 칸씩
        todo.setTitle(rs.getString("title"));    // 손으로
        todo.setCompleted(rs.getBoolean("completed"));
        return todo;
    }
}
```

```
 ✔  DB 와 통신은 된다
 ✘  컬럼이 10개면 10줄.  하나 추가하면 전부 고친다
 ✘  테이블마다 이 코드를 또 쓴다
 ✘  setter 가 필요해진다  →  아무나 값을 바꿀 수 있게 된다
```

**이 불편함을 없애려고 나온 게 위의 세 개입니다.**

## ② JPA — 실행되지 않습니다

여기가 제일 헷갈렸습니다.

```
 JPA        interface   "이런 메서드가 있어야 한다"는 약속      명세서
 Hibernate  class       그 약속을 실제로 구현한 코드           제품
```

증거는 import 한 줄에 있습니다.

```java
import jakarta.persistence.Entity;
import jakarta.persistence.Id;
```

`jakarta.persistence` 패키지를 열어보면 **`@Entity`가 무슨 일을 하는지는 안 적혀 있습니다.** "이 클래스는 엔티티다"라는 표시만 있어요.

```
 EntityManager          jakarta.persistence     interface
      ↑ implements
 SessionImpl            org.hibernate.internal  class
```

`em.persist()`를 호출하면 **실제로 도는 건 Hibernate의 `SessionImpl.persist()`** 입니다.

### 명세라는 걸 모르면 못 고치는 버그

```java
import org.springframework.data.annotation.Id;   // ❌ 컴파일은 된다
import jakarta.persistence.Id;                   // ✅
```

Hibernate는 `jakarta.persistence.Id`만 봅니다. 다른 패키지의 `@Id`는 **모르는 애노테이션이라 그냥 무시**합니다. PK 없는 엔티티가 되어 실행할 때 죽습니다.

### JPA가 정한 것

```
 애노테이션     @Entity  @Id  @OneToMany  @Column
 인터페이스     EntityManager  EntityTransaction  Query
 질의어        JPQL — 테이블이 아니라 객체를 대상으로 하는 쿼리
 개념          영속성 컨텍스트, 엔티티 생명주기
```

**"영속성 컨텍스트를 둬라, 변경을 감지해라"가 JPA 명세에 적혀 있고, "이렇게 구현했다"가 Hibernate입니다.**

## ③ Hibernate — 실제로 일하는 놈

같은 조회가 한 줄이 됩니다.

```java
Todo todo = entityManager.find(Todo.class, 1L);
```

```
 ┌─ SessionFactory ───────────────────────────────────┐
 │    앱 시작할 때 1개.  무겁다                          │
 │    ├ 매핑 정보     @Entity 를 전부 읽어서 보관         │
 │    ├ Dialect      DB 별 SQL 방언 (H2Dialect ...)    │
 │    └ 커넥션 풀 연결                                   │
 └────────────────────────────────────────────────────┘
              │  트랜잭션마다 하나씩
              ▼
 ┌─ Session  (= EntityManager) ───────────────────────┐
 │  ┌─ 영속성 컨텍스트 ──────────────────────────────┐  │
 │  │   1차 캐시     [ ]   엔티티 보관                │  │
 │  │   스냅샷       [ ]   변경 감지용 사본            │  │
 │  │   쓰기 지연     [ ]   보낼 SQL 대기열            │  │
 │  └───────────────────────────────────────────────┘  │
 └─────────────────────────────────────────────────────┘
```

**"1차 캐시", "변경 감지", "쓰기 지연"은 전부 저 안의 자료구조입니다.** 마법이 아니라 `Map` 세 개예요.

> 영속성 컨텍스트가 어떻게 동작하는지는 따로 정리했습니다.

## ④ Spring Data JPA — 구현체를 안 씁니다

```java
public interface TodoRepository extends JpaRepository<Todo, Long> { }
```

```java
Optional<Todo> todo = todoRepository.findById(1L);
```

**구현 클래스를 쓴 적이 없는데 돌아갑니다.** 런타임에 `SimpleJpaRepository` 프록시를 만들어 빈으로 등록해주기 때문입니다.

```
 ① 구현체를 런타임에 생성       ★ 본체
 ② 기본 CRUD 공짜              save / findById / findAll / delete
 ③ 메서드 이름 → 쿼리           findByCompleted(...)
 ④ @Query / 페이징             이름으로 안 되면 직접 JPQL
```

③은 이렇게 동작합니다.

```java
List<Todo> findByCompleted(boolean completed);
```

```
 메서드 이름 파싱     find / By / Completed
        ↓
 JPQL 생성         select t from Todo t where t.completed = :completed
        ↓
 Hibernate 가 SQL 로 번역
        ↓
 select ... from todo where completed = ?
```

## 뭘 뭐랑 비교해야 하나

### JPA ↔ Hibernate : 명세 ↔ 구현

```
                 JPA                      Hibernate
 ───────────────────────────────────────────────────────────
 정체            명세 (약속)                구현체 (제품)
 구성            interface, 애노테이션       class
 실행            되지 않는다                 실제로 돈다
 패키지          jakarta.persistence       org.hibernate
```

### Hibernate ↔ JDBC : 비교 대상이 아닙니다

```
 Hibernate   SQL 을 만든다      "select t.id from todo t where t.id=?"
     ↓
 JDBC        그 SQL 을 보낸다    PreparedStatement.executeQuery()
```

**둘 다 씁니다. 항상.** 자바에서 DB로 가는 길은 JDBC뿐이고 Hibernate도 그 길을 씁니다.

### 진짜 선택지 : JPA ↔ MyBatis

```
          JPA / Hibernate             MyBatis / JdbcTemplate
          SQL 을 만들어준다              SQL 을 내가 쓴다
                 ↓                           ↓
 ┌──────────────────────────────────────────────────────┐
 │                       JDBC                            │
 └──────────────────────────────────────────────────────┘
```

```
                 JPA / Hibernate           MyBatis
 ─────────────────────────────────────────────────────────
 중심             객체                      SQL
 단순 CRUD        거의 안 짠다                매번 짠다
 복잡한 통계 쿼리   어렵다                     쉽다
 DB 교체          Dialect 가 흡수            SQL 을 다시 쓴다
 성능 문제        숨어 있다 (N+1 등)          SQL 이 보이니 예측된다
```

면접에서 **"JPA vs MyBatis"는 나와도 "Hibernate vs JDBC"는 안 나옵니다.**

## `findById(1L)` 전체 추적

```
 todoRepository.findById(1L)
     ↓
 ① SimpleJpaRepository.findById()        Spring Data JPA 가 만든 프록시
     ↓
 ② EntityManager.find(Todo.class, 1L)    JPA 명세의 인터페이스
     ↓
 ③ SessionImpl.find()                    Hibernate.  여기부터 진짜 일
     ├─ 1차 캐시 확인      있으면 여기서 끝. SQL 안 나감  ★
     └─ SQL 생성          @Entity / @Column 을 읽어서
     ↓
 ④ PreparedStatement.executeQuery()      JDBC
     ↓
 ⑤ Driver → DB → ResultSet
     ↓
 ⑥ Hibernate 가 ResultSet → Todo 객체로 매핑   ← ① 에서 손으로 하던 그 일
     ↓
 ⑦ Optional<Todo> 반환
```

## 정리

```
 JDBC              자바와 DB 사이의 표준 연결 API.  모든 경로의 종착점
 JPA               ORM 명세.  인터페이스와 애노테이션의 집합
 Hibernate         JPA 구현체.  SQL 생성, 영속성 컨텍스트, 변경 감지
 Spring Data JPA   JPA 위의 추상화.  리포지토리 구현을 런타임에 생성
```

**선택의 여지가 있는 지점은 하나뿐입니다.** SQL 작성을 ORM에 맡길 것인가(JPA), 직접 쓸 것인가(MyBatis). 어느 쪽을 고르든 그 아래는 JDBC로 수렴합니다.

### 면접에서 물으면

> **JPA와 Hibernate의 차이가 뭔가요?**
> JPA는 자바 ORM 표준 명세이고 Hibernate는 그 구현체입니다.
> JPA는 `jakarta.persistence`의 인터페이스와 애노테이션으로만 구성되어 있어
> 그 자체로는 동작하지 않습니다. `EntityManager`가 인터페이스이고
> Hibernate의 `SessionImpl`이 구현체입니다.

> **그럼 JDBC는 어디에 있나요?**
> 가장 아래 있습니다. Hibernate가 SQL을 생성하면 결국 JDBC의
> `PreparedStatement`로 전송됩니다. 자바에서 DB에 접근하는 경로는
> JDBC 하나뿐이라, Hibernate와 JDBC는 대체 관계가 아니라 상하 관계입니다.
